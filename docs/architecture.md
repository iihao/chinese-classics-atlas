# Chinese Classics Atlas · 单仓库架构（第二部作品：三国交互切片）

一个仓库、一个站点、一次构建与部署。作品是站内路由与独立数据包，不是独立 GitHub 项目。

## 当前可运行的纵向切片

- `/`：系列首页，从 `works/catalog.json` 读取已上线作品。
- `/works/honglou/`：原红楼完整界面，原有 hash 路由保持不变；根目录旧链接 `/#graph`、`/#item/pl-baoyu` 等重定向到红楼。
- `/api/works/honglou.json`：红楼专属数据包。本地服务与静态站使用同一 URL；首页不加载这份数据。
- `/works/sanguo/`：三国小说叙事的交互切片；源数据 `works/sanguo/data.json`，构建后由 `/api/works/sanguo.json` 按需加载。页面支持势力与关系类型筛选、人物/别号搜索、关系与事件节点、连线关系、回目详情，以及人物/事件/地点互相跳转。
- `/en/`：既有英文落地页（暂时介绍红楼；后续改为系列英文首页）。

旧 `/api/bootstrap` 暂作为本地兼容端点；新前端不使用它。原有数据生成脚本、SQLite schema 和红楼渲染器暂不迁移，以保证迁移期间的页面与条目不退化。

## 目录与演进边界

```
works/catalog.json             已上线作品目录（只注册真正可构建的作品）
works/honglou/index.html       红楼专属页面
css/atlas.css                  共享外观层：配色令牌、顶栏、页头、工具条、控件、页脚、响应式
works/sanguo/index.html        三国页面
works/sanguo/data.json         三国核心叙事数据（人物、关系、事件、地点、回目、小说/史传说明）
works/sanguo/encyclopedia.json 三国百科档案层（生卒/籍贯/官职/交战结果 + 百科外链，不含正文）
tools/sanguo_data.py           合并核心数据与百科档案，供本地 API 与静态构建共用
works/shuihu/data.json         水浒数据（人物座次/山头/结局、关系、事件、地点、招安阶段；由 tools/build_shuihu.py 生成）
js/works/shuihu.js             水浒渲染器（关系图、座次表、招安进程、人物、事件、地点）
css/sanguo.css                 三国专属样式（只剩图谱、人物卡、大事记、弹窗内容）
css/xiyou.css                  西游专属样式（关系图、西行路线、难簿、隐语）
css/shuihu.css                 水浒专属样式（关系图、座次、招安）
css/style.css                  红楼专属样式（谱系、关系图、判词、隐语、府邸、回目、数据）
js/works/sanguo.js             三国交互渲染器（势力、搜索、图谱、详情、大事记）
js/app.js                      目前仍是红楼专属渲染器
js/map-art.js                  红楼府邸绘图，不能视为通用地图组件
db/seed.json                   红楼源数据的生成结果
tools/validate_works.py        作品注册、引用校验入口
tools/build_static.py          唯一站点构建器
dist/api/works/<id>.json       按作品拆包（构建产物）
```

三国先以独立的小规模切片验证数据边界，使用自己的渲染器与样式；没有把红楼 `app.js` 的谱系、判词、府邸逻辑复制过去。红楼与三国的交互模式相近（筛选、搜索、邻域高亮、详情、来源），但实现尚未合并。等第三部作品出现、或两部作品都需要同一处改动时，再按真实重复抽取公共组件，避免过早抽象。

作品到第四部时，重复已经落在样式上（四份顶栏、页头、工具条几乎逐行相同），于是抽出 `css/atlas.css`：

- **一份令牌。** 纸、墨、线、朱、金、青，字号、圆角、阴影、焦点环，全部只在 atlas 里定义。作品 css 里不再写调色板；
  每部作品的身份色（朱砂深红、赭红、青绿、芦灰）由 `<html data-work="…">` 声明，写在 atlas 的 `html[data-work="…"]` 里。
- **一套外壳。** 顶栏与作品切换、页头、数据条、读法说明、工具条、筛选片、分段控件、搜索框、缩放组、页脚、断点，全部共享。
- **加载顺序**：作品 css 在前，`atlas.css` 在后。同名部件由 atlas 收口，作品文件只留自己的部件；
  以后改配色或控件尺寸，只改一个文件。
- **不动渲染器。** 三个作品的 `js/works/*.js` 与红楼 `js/app.js` 继续各自渲染自己的 DOM，类名不变：统一发生在 CSS 层，
  不引入框架，也不合并交互逻辑。

三国数据契约的公共约定：`version` / `workId` / `source` / `layer`、稳定的 ASCII id、人物/地点/事件分表、关系带 `group` 与回目、事件按回次排序、出场人物与地点必须可解析。三国事件与人物另有 `history` 字段，用来标注小说叙事与史传记载的差异；这一层不能省略。

百科档案单独成层，不和核心叙事混写：`encyclopedia.json` 只补充结构化事实与外链，`sanguo_data.py` 在读取时合并。这样网络抓取结果、人工校正和外链可以独立替换，不会污染关系、事件与回目。百科正文不落库，只保留事实字段和链接，避免版权与版本漂移问题。

新增作品的最小交付：有自己的数据源、构建输出、校验规则、入口页面（或已验证的公共页面）和 CI 冒烟测试，再在 catalog 中登记。
西游按此接入，另外留下三条约定：

- **可选模块各写各的**：判词/府邸是红楼的，路线/难簿是西游的，不抽公共接口；只有两处以上出现同类需求时才考虑提取。
- **位置类数据不写死在源里**：西游路线站点只记 `leg` 与 `chapter`，坐标由渲染器算；否则每加一个站点都要重排整条线。
- **解释性内容必须分级并给依据**：西游的隐语每条带 `basis` 与 `verdict`（通行/一说/存疑），难簿每条带 `omen`/`actual`/`verdict`；
  校验器与 CI 断言这些字段存在且取值受限。红楼的谶语判定、三国的「小说与史」是同一原则的不同形态。不能只改目录宣称作品已上线。数据包带作品标识时应校验跨作品引用，出处必须标明作品/版本；三国小说情节与史料不能当同一层事实。

红楼文字小游戏（`works/honglou/game/`）是独立页面，不并入图谱 SPA，避免为少数玩家加载整套图谱脚本。
引擎只认「场景 / 选项 / 旗标 / 三条暗线 / 册子」这一层，剧情全在 `scenes.json`。这套契约足够通用，
等第二部作品要写游戏时再抽成公共模块；现在只有一部作品，抽取为时过早。

水浒沿用「每部作品自己的渲染器与数据契约」的做法，新增的是作品自身的结构：座次（天罡必收全、序号唯一）、
山头分组、结局分类与招安阶段。它的座次表不是通用组件——三国没有座次、西游没有招安，强行抽象只会造出空字段。
等第四部作品也需要同一张可排序表格时再抽。

三国校验当前覆盖：势力与分组取值、人物/地点/事件 id 唯一、事件按回次递增、出场人物与地点可解析、每条关系两端存在且同一对人物不重复连线、每个人物至少有一条关系；百科档案覆盖全部人物，事实字段与外链格式合法。

## 构建与验收

```bash
python3 tools/build_seed.py
python3 tools/validate_works.py
python3 db/init_db.py --force
python3 tools/build_static.py
./start.sh
```

访问 `/`、`/works/honglou/#graph`、`/works/sanguo/#graph`；根路径 `/#graph` 应转到红楼；本地预览与静态产物应有一致的作品数据。Pages 与 CI 都执行作品校验。不要把 `dist/`、工作区运营材料或内部截图脚本放进发布目录。
